# 小凯实验室数采平台

这是一个使用 PySide6 + Qt Quick/QML 原生界面、运行在采集电脑上的独立 App，提供遥操作采集、UMI rosbag 采集和 Ego 占位页，**不提供、不启动 HIL-SERL**。
遥操作、相机预览、Pico/XR 和编码器数据都留在本机；完成的 Episode 由后台上传器直接登记到数据平台的数据列表。

## 当前功能

- 遥操作：第一步填写任务名称、选择机器人；第二步进入对应机器人的独立操作页。目前支持智元 G2 与 Tianji 天机。G2 保留设备检查、速度/幅度、姿态预览和手动控制。两种工作台均同时显示三路相机，主相机居中，左右腕部画面可互换位置。任务名称随录制数据上传。
- G2 遥操作采集：运行期间使用 Pico 手柄 `A` 开始一段，`B` 完成一段；完成后自动进入平台上传队列。
- UMI：设备检查时自动启动 Galaxis VR 服务和 PICO VR APK，支持双臂/单臂配置、启动服务、开始/完成/放弃一段、监看视频和手动重试上传。
- Ego：只保留清晰的空功能位，目前不会连接设备或创建空数据。
- 桌面界面：按原 WebKit 版重建页面布局、配色、相机预览和编码器曲线，Qt Quick 3D 加载完整 CAD 模型；窗口自适应，已移除外部浏览器入口。
- 平台账号：支持“记住账号密码”和“自动登录”；服务器签发登录令牌，后台上传会自动使用当前账号并记录用户名。

UMI 传感器读数、闭合最小值和监视曲线统一以度数（°）显示。设备确认阶段读取传感器
原始角度；将夹爪闭合后确认最小值，采集监视与保存使用以该位置为 0° 的相对角度，
左右夹爪打开均沿正方向增加。标定后因误差出现的负相对角度统一发布、显示并保存为 0，
监视接口保留与记录相同的数值精度，仅在界面转为度数后显示两位小数。
启动采集时夹爪已经张开，也保留相对于标定位置的角度，
不会把每段首帧重新当作零点。串口、标定参数和 rosbag 内的 JointState 沿用原采集代码
的弧度单位（例如 30° 保存为 π/6 rad），保存值已扣除闭合零点，不是上电绝对角度。
缺少或无效的零点标定会阻止启动；采集服务运行期间需先结束服务才能重新标定。

UMI 设备确认和采集监控页面的每路相机画面下方提供独立亮度调节，可拖动滑块、输入
数值或恢复硬件默认值。范围和步长读取相机实际能力，不支持的相机会显示提示。
调节直接作用于相机硬件，预览与保存图像使用相同的亮度；设备确认时已调好的亮度会
传入原 ROS 相机控制配置，进入采集后不会被重置为 0。

## Tianji 天机

在遥操作采集的第一步选择 **Tianji 天机**，下一步进入独立工作台。「上传曲线」可选双臂、左臂或右臂，只决定上传哪些关节和夹爪曲线；遥操作、手动控制和本机采集始终使用双臂与双夹爪，三路相机照常采集。

- 比例、关节速度/加速度位于模式与「其它参数」之间，可直接输入或上下调节；左右夹爪速度和 Kp/Kd 位于小窗。每次进入工作台使用默认值，当次修改自动保存，左右夹爪速度默认均为 10 rad/s。夹爪协议沿用当前力位模式，不自动切换模式。
- 网线连接默认控制器 `192.168.1.190`，连接 Pico 后点击「检查设备」，沿用已安装的 Galaxis VR/RoboticsService。只有新鲜机器人及 VR 数据在线才可开始。
- 「检查设备」会验证 Galaxis VR 是否收到时间戳持续更新的数据。已有连接失效时重建本机 SDK 接收进程，并最多重启一次本机 Galaxis 服务；健康连接保持不变。仅在遥操作、采集和 UMI 均停止时允许检查恢复，不重启 PICO 应用或远端控制器。恢复后仍无新数据会提示检查头显 WORK / Head / Controllers / Send Data，不会把端口监听误报为 VR 数据在线。
- 「检查设备」遇到预览异常时，在遥操作和采集停止后释放电脑本地的相机连接、等待接收线程退出，再重新连接预览；三路画面正常时保持现有连接。不会通过 SSH、远端恢复接口或系统命令重启控制器服务，也不保存故障快照或恢复报告。独立的 `fusion-camera` 运行在控制器上，本机没有该服务；控制器故障仍存在时明确提示本地重连无法解除。
- 遥操作 TCP 为每只夹爪两侧固定转轴所在平面与电机轴线的交点，沿法兰 +Z 方向距安装面中心约 142.226 mm；不随夹指开合变化。左右臂分别使用 URDF 的 `grasp_center_L/R`，控制与显示同步。该位置为 CAD 名义值，更新后须重启 App 加载。
- 模型来自原 `dual_arm_with_grippers.urdf` 和 CAD 网格，包含底座、固定件、双臂和夹爪；支持旋转/缩放。机械臂显示反馈角度，无遥测时显示零点参考；没有夹爪反馈时开度仅示意。
- 三路相机映射为 `usb-1 / usb-2 / usb-4`，分别对应主相机、右腕部相机、左腕部相机；复用 app 内 `fusion_camera_stream` 客户端。在原图像区域内同时显示三路，各自标注身份；右上角可选择左右腕部画面的排列并自动记住，只改变显示位置，不改变相机身份或录制映射。预览使用 `teleop_observation`，只缓存最新帧、不写 Episode。相机失败单独提示，不冒充在线。
- 手动控制为每次 10° 步进，复位默认将双臂各 **7 个关节回零**，不重新标定硬件零点、不自动改变夹爪开闭。完整路径预检后，手动移动和复位速度上限均为 10°/s；手动移动加速度上限为 4°/s²，回零加速度上限为 5°/s²。均受页面中更低的参数上限约束，短行程实际速度取决于平滑加减速。可保存/删除本机姿态。
- 「开始遥操作」后，握把接管对应机械臂、扳机控制夹爪；右手 **A 开始采集、B 结束并保存**（也支持 X/Y）。等待页面显示“采集中”再开始本轮动作；按住按键不会重复创建回合，同时按开始/结束时结束优先。B/Y 不停止遥操作运动；使用「停止控制」或硬件急停停止运动。
- 每侧接管时，以该臂当前 TCP 位姿为起点。首次接管请平视机器人前方：该次头显水平朝向作为双臂共享映射基准，忽略俯仰、侧倾；松握把、转头和短暂断流重新锚定均不改变方向。停止并重新开始遥操或新 VR 会话会重新建立方向基准。修改控制代码后需停止控制并重启 App，让控制进程重新加载。
- 持续接管不再按距本次起点 25 cm 截断位置目标，位置与朝向仍按同一接管基准相对映射；实际运动仍受机械臂可达范围、关节/腕部限位、速度/加速度、碰撞检查和 VR 跳变/失联保护约束。超出可达范围时应松开重新定位，不要继续积累手柄目标偏差。
- 天机遥操作、手动移动和复位均恢复改阻抗前的位置控制流程（`state=1`），发送关节位置目标；不调用 PD 前馈接口，不读取或写入 `JointPIDCtlType`，不配置关节阻抗增益、不保存控制器参数。目标更新频率仍为 100 Hz，原有关节限位、速度/加速度、碰撞和失联保护保持不变，夹爪协议不变。回退 App 代码不会清除控制器已保留的故障或恢复其运行时参数，仍须通过正常停机和预检后才能启动。
- 「其它参数」提供左右夹爪各自的打开/关闭角度，单位为 rad（与文件一致），初值读取 `teleop_control/vendor/tianji/teleop/gripper/config.json` 中对应侧的 `open_rad` / `closed_rad`。停止控制和采集后修改会自动同步该文件及参数指纹，下次遥操作或手动控制生效，界面开度映射同步更新；不改变电流、增益或安全余量。开闭端点必须在启动单圈范围内且行程大于两倍安全余量，允许开闭方向相反；文件不可写或数值不合法会提示保存失败。请按实际机械标定设置，不以软件允许范围代替机械限位。
- 数据在 App 内 `teleop_control/runtime/tianji/episodes/<回合>/` 保存，每轮最长 600 秒。三路相机统一命名为 `head_color`（usb-1）、`right_color`（usb-2）、`left_color`（usb-4），只保存 640×480 JPEG，不创建 native 目录。MJPEG 与 YUYV 使用你更新后的采集模块转换。
- 本机保存实际双臂关节、双夹爪反馈、夹爪对齐来源与误差、实际 SDK 接受的关节指令以及相机索引；`record/actions.jsonl` 与 bundles 中的 action 来自命令，不以关节反馈伪造。上传时按「上传曲线」筛选临时 tar 内的关节、夹爪、动作和对齐记录，三路图像及时间戳不变，本机完整原始文件不改写。元数据分别记录实际控制范围 `controlled_sides` 和上传范围 `upload_sides`；已上传回合不自动重传，旧回合沿用原有控制范围与存档格式。
- B/Y 正常结束后，写完索引、时钟对齐、元数据和校验结果，最后才创建 ready 标记。复用 G2 的上传队列：登记导入批次 → 申请上传地址 → 上传单回合 tar → 注册 Tianji Episode → 保存上传回执；同账号登录时失败自动重试、重开 App 后继续、成功后不重复上传。操作栏在“检查设备”左侧显示本次完成的 Episode 数量和采集状态；采集或上传失败时显示原因。
- 缺帧、反馈断线、相机异常、磁盘空间不足等中断会保留不完整回合，但不加入自动上传队列；完整回合的频率/标定质量结论也会保存在元数据中。停止遥操作时仍在录制的回合按中断处理，应先按 B 完成本段。
- 相机预览与录制使用同一独立服务，开始录制前先释放预览；录制中使用落盘帧供预览，结束后恢复预览，避免双客户端抢占。控制器报告审计故障（如 `dmesg_sha256`）时会显示原因，不绕过锁定。
- 页面失联超过 8 秒请求停止；返回配置时断开天机设备。进程用独占锁和单个厂家连接统一处理遥测、遥操作及手动控制，避免相互抢占。模拟启动 `--mock` 禁止连接天机硬件。

所需 SDK、运动学配置及碰撞模型仅保留在 `teleop_control/vendor/tianji`，运行不依赖桌面的原 SDK 目录；来源和适配点见其中 `UPSTREAM.json`。已同步此次更新的夹爪标定、加速度限制、控制周期和按键定义，也同步既有相机客户端的新色彩转换及恢复接口；未自动调用相机恢复。

可选环境变量：`TIANJI_PYTHON` 指向已安装 `numpy`、`pydantic`、`xrobotoolkit_sdk` 的解释器；默认复用 `TELEOP_GDK_PYTHON` 或现有 bot 环境。相机凭据默认保存到当前用户的 `~/.config/xiaokai-lab-data-collection/tianji-camera/client.json`（遵循 `XDG_CONFIG_HOME`），不随版本工作区变化；也可用 `TIANJI_CAMERA_CREDENTIALS` 指定。首次使用可在相机画面右上角设置按钮导入 SDK 的 `client.json`，须保留它引用的证书；软件验证后私密保存配置和证书，再点击「检查设备」连接。旧版工作区的有效配置会自动迁移。导入时须先停止遥操作和采集。换电脑需导入该设备的授权配置并连接实际设备，分发包不包含本机凭据。

相机服务 v2.3.2 若在正常伺服启停后出现 `Audit changed: dmesg_sha256`，先核对控制器日志。确认仅为已知启停消息、停止控制和采集并保持 App 打开后，可在电脑本机的 app 目录运行 `.venv/bin/python scripts/fix_tianji_camera_audit.py --install`。脚本核对空闲状态及服务源码哈希，通过交互式 SSH 备份日志和源码，仅更新相机审计并重启独立的 `fusion-camera`；启动失败回退。修正只允许运动采集期间的精确伺服启停消息，保留原始日志哈希、其它审计检查和静止模式的严格检查。未知服务版本或其它故障会拒绝安装。完成后点击「检查设备」恢复预览；单纯修改电脑端代码不会更新控制器。

首帧超时可先运行 `.venv/bin/python scripts/diagnose_tianji_camera.py` 做只读诊断，报告保存在 `teleop_control/runtime/tianji/camera-controller-diagnostics.json`。确认是主相机 `1-1`、身份为 `0bda:5883`、接口空闲且无进程和内核驱动占用后，可显式添加 `--reset-main-camera` 做一次设备级 USB 复位。该选项要求 App 控制及采集停止，仅针对主相机设备节点调用 USBDEVFS_RESET，并重启独立相机服务；不会重置 USB 主控制器或重试失败的复位。随后验证三路取流，结果仍写入诊断报告。此操作不是断电重启，不保证解决相机硬件故障。[Linux USB 接口说明](https://www.kernel.org/doc/html/v4.10/driver-api/usb.html)

若诊断确认右腕部 `usb-2` 发生 USB 掉线，且服务报告 `Camera interface did not return to idle; Audit changed: dmesg_sha256`，可在人工检查日志后运行 `python3 scripts/restart_tianji_camera.py --restart`。工具只接受已核对的 v2.3.2 故障和服务源码：要求 App 待机、无录制/预览，核对相机身份、占用、接口和连续 5 秒稳定性，备份故障证据后仅重启独立相机服务，再进行三轮各 10 秒的实际图像解码及正常收尾验证。密码由 SSH 在终端读取。不会更改审计规则、复位 USB 或控制机械臂；任一轮失败立即停止，报告保存在 `teleop_control/runtime/tianji/camera-restart-verification.json`。该工具用于恢复已稳定的连接，不能代替对反复掉线的接线、供电或驱动问题的处理。

验证范围：离线模型/控制/API/页面测试，以及三种模式、合成 MJPEG/YUYV → A/B 回合保存 → 模拟平台上传、失败重试和账号切换测试。尚未进行真实机械臂运动或真实平台上传验收。

## 首次安装

分发给其他电脑时使用完整 `.deb`，执行 `sudo apt install ./实际文件名.deb`。
它会安装桌面及 UMI 系统依赖并导入包内镜像。以下脚本步骤仅适用于源码开发环境，
完整安装版不需要另装 Node/npm 或手工构建采集镜像。

在本文件夹打开终端：

```bash
./install-app.sh
```

安装完成后，双击 `数据采集台.desktop`，或从 Ubuntu 应用菜单打开
“小凯实验室数采平台”。它会以独立桌面窗口运行，不显示浏览器地址栏；关闭窗口时
会自动停止该 App 启动的后台采集服务。

安装路径不再要求是某位开发者的桌面目录。请用实际使用 App 的普通用户安装，
不要用 sudo 运行整个安装脚本。安装器会根据当前目录生成用户启动器、应用菜单和
K 图标；首次缺少 .env 时才从模板创建，已有云平台地址和其他配置不会被覆盖。

源码换电脑后需要重新运行 install-app.sh，不要直接复用原电脑的 .venv。
移动安装目录后也应重新安装，以更新 Python 可编辑安装路径和快捷方式。
只刷新当前电脑的快捷方式、不安装依赖或启动采集，可运行：

    python3 scripts/install_desktop.py

GDK/bot 环境及厂商辅助启动器的默认路径按当前用户的主目录查找；非标准位置仍可
通过 TELEOP_GDK_PYTHON、TELEOP_GDK_APP_ROOT 和厂商脚本原有环境变量指定。
完整分发包的构建与安装见 `打包与分发.md`。

直接运行桌面界面（源码环境）：

```bash
./start-app.sh
```

无硬件启动使用 `--mock`。仅启动后台服务使用 `./start-app.sh --backend-only --no-browser`。

独立 App 默认使用 `8011`，以避免与原数据平台的 `8010` 采集服务冲突。如需
更换端口，请同时修改 `.env` 中的 `LOCAL_CONTROL_PORT` 和 `LOCAL_CONTROL_URL`。

## 桌面兼容与可选依赖

完整 `.deb` 安装版通过系统包管理器安装 Docker、Compose、ADB 与桌面依赖，
在安装阶段导入包内的离线 UMI/ROS 镜像，并为安装用户配置设备访问权限。
系统依赖首次安装可能需要联网；UMI 镜像已经在包内，采集时不再下载或编译。
PICO 应用也随包提供：连接并授权 USB 调试后，“检查设备”会在头显尚未安装
Galaxis 时安装它，保留头显上已有的版本。相机角色、夹爪闭合位置和头显授权
属于实际设备设置，不能用开发电脑的设置代替。
未安装 Docker 的开发版仍能打开界面和登录；若检测到已有采集会话或可连接的
采集监控服务，仍保留安全停止检查。

桌面窗口使用 PySide6 6.8.3 与 Qt Quick，界面与三维模型均由 Qt 绘制，不使用 WebView，也不启动网页服务器。
跟随桌面字体缩放，可用 `.env` 的 `APP_UI_SCALE` 覆盖；软件渲染使用 Mesa，仍显示完整 CAD 模型。
默认最大化，随窗口大小重新排列，小窗口可滚动；已移除“在浏览器打开”入口。
如果显卡兼容性导致白屏或闪烁，可从应用图标菜单选择“软件渲染模式”，
或执行 `xiaokai-lab-data-collection --software-rendering`。

## IP / 云服务器配置

所有运行配置都在根目录的 [`.env`](.env)，复制模板可参考 [`.env.example`](.env.example)。
切换平台或云服务器时主要修改：

```dotenv
PLATFORM_API_URL=https://api.example.com
PLATFORM_WEB_URL=https://platform.example.com
```

首次启动 App 时输入平台账号和密码，可选“记住账号密码”或“自动登录”：

- 不勾选：重新打开 App 时手动输入账号和密码。
- 记住账号密码：重新打开后恢复账号，可直接点击登录，密码不回传到界面。
- 自动登录：同时启用记住账号密码；重新打开后向平台重新验证，失败则留在登录页，不循环重试。
- 关闭 App 保留勾选项，但仍停止采集并清除当次令牌；主动“退出登录”会取消两项、清除保存的账号密码和令牌。

记住的密码通过系统 libsecret/Secret Service 保存在当前桌面用户的钥匙环中，不写入
JSON、浏览器存储或安装包。钥匙环不可用时不退回明文保存，可以取消勾选后正常登录。
Ubuntu 源码安装如缺少组件，安装 `gir1.2-secret-1` 和 `gnome-keyring`；桌面钥匙环需已解锁。
对应实现依据 [libsecret Python 文档](https://gnome.pages.gitlab.gnome.org/libsecret/libsecret-python-examples.html)。
平台地址变更后不会把旧平台保存的密码自动发送到新地址。
平台签发的登录令牌保存在当前系统用户的私有配置目录中，并自动用于后台上传，
不需要在 App 中配置平台密钥。

修改 `.env` 后重启 App 即生效；启动器会自动生成不含密钥的浏览器配置。
不要把带真实密钥的 `.env` 提交到 Git。

## 数据流

```text
Pico / XR / G2 / USB 相机 / 编码器
              │
              ▼
      本机采集服务（127.0.0.1）
              │  完成后后台上传
              ▼
       PLATFORM_API_URL
              │
              ▼
       平台 Episode 数据列表
```

- 遥操作本地目录：默认 `~/agibot_episodes/dual_arm`
- UMI 本地目录：默认 `~/galaxis_data/rosbags/<任务>/<回合>`
- 上传成功会在 Episode 目录写入 `.data-platform-uploaded.json`，避免重复上传。
- 登录必须由平台验证账号密码；平台不可连接时停留登录页，不允许离线进入。已登录后平台断线仍可操作设备，不弹采集连接提示，平台离线时不开始新的数据保存。后台每 2 秒检查平台会话，最长 10 秒后过期失效。已经开始的回合仍正常收尾，已有文件保留，恢复平台并登录原采集账号后自动重试上传。
- `.env` 中 `PLATFORM_API_URL` 配置实际的平台 API 地址；`127.0.0.1:8000` 仅连接本机平台。使用云端时同时填写 `PLATFORM_WEB_URL`。平台恢复后可以正常登录。

切换平台时用同一条命令同时更新两个地址，然后重启 App：

```bash
python3 scripts/configure_platform.py --api-url https://api.example.com --web-url https://platform.example.com
```

请替换为实际云端地址（允许 API 和网页使用不同域名或端口）。命令会一次性写入
两项配置并保留其他设置；启动和打包也会校验地址，避免云端 API 搭配本机网页。
切回本地时分别填写 `http://127.0.0.1:8000`、`http://127.0.0.1:5173`。


### UMI 录制就绪

开始回合时，录制器先等待当前配置启用的相机、PICO 位姿和夹爪消息实际写入
MCAP，才报告录制成功并开始回合计时。仅创建进程、相机预览正常或已有
文件头不会视为就绪；单臂模式不等待关闭侧，低频状态/静态标定话题不阻塞启动。
最多等待 8 秒；超时会说明缺少的通道，进程退出会报告退出码，失败回合不进入
保存和上传流程，未完成文件不会提交平台。不会改写已有回合。

本次更新新增 Python `mcap>=1.2.2,<2` 依赖；从源码更新的电脑需先在
`umi_collection/vendor/galaxis` 中运行 `docker compose build galaxis_core_builder`，
再退出并重新启动 UMI 采集服务。录制开始请求允许等待就绪及失败清理，不应
在等待过程中重复按开始。其他电脑使用新镜像/重新打包的 App。

### UMI 保存与平台导入导出

新 UMI 回合的相机画面保存为 H.264 MP4，不使用 HDF5。停止回合后先从临时
MCAP 转换，逐帧校验视频并核对所有非图像消息，再发布完成标记和清理原始大包。
`media/left.mp4`、`right.mp4`、`center.mp4` 对应实际启用的相机；
`media/signals.mcap` 无损保留关节、位姿等消息，`media/video-manifest.json`
保留每帧原始 ROS 时间戳、消息头、序号和文件校验值。视频采用 CRF 20 有损编码，
保持源分辨率和帧数。中断或转换失败时保留原包，重新启动采集服务后重试未完成保存。
平台需要同时部署本次 worker 和网页导入代码；原始文件下载包含 MP4、传感器数据及
时间戳清单，转换后的预览、曲线和 LeRobot 导出保持原接口。

旧回合继续兼容 ROS 2 rosbag（MCAP）。旧目录包含单个
`<回合>_0.mcap`、`metadata.yaml` 和 `meta.json`；图像、位姿、夹爪、标定、
按键和时间戳按现有录制话题保存在 MCAP 内。双臂/单臂硬件配置继续决定录制话题。

录制器停止并刷盘、验证回合元数据后，原子写入 `meta.json`。上传器只扫描
已收尾的回合，并检查 MCAP 首尾标记及元数据引用。平台登记采用
`source=rosbag`、`format=rosbag`，存储键为 `raw/mcap/metadata/meta`，由平台
现有 rosbag 转换任务生成预览、曲线和可导出的数据。原始数据下载包含上述三个文件。
失败可重试，成功登记保留回执避免重复；账号切换后等待原采集账号重新登录。

历史 HDF5 文件保留，不会批量改写；旧进程恢复时仍保留 HDF5 收尾保护。
源码更新后重新启动 App 和 UMI 采集服务；已安装的 `.deb` 需要重新构建包含
更新录制器的 UMI 镜像并打包安装，新源码不会自动替换旧安装包中的镜像。

## 源码开发电脑依赖

历史文件的独立 HDF5 质量检查：运行 `python3 scripts/check_hdf5_quality.py "/路径/文件.h5"`，
会生成离线图表报告、0～3 阶差分/Z-score 和异常明细；不会修改原文件。
参数与计算约定见 [HDF5数据检查.md](HDF5数据检查.md)。

- PySide6 6.8.3 / Qt Quick（完整 deb 已内置）；Qt 系统图形库由 apt 安装
- Python 3.12+
- 智元 GDK / bot Python 环境
- `adb`、Galaxis VR 服务以及 UMI Docker/ROS 环境

厂商运行时代码、遥操作采集器、UMI 工程、前端和启动脚本都包含在本文件夹内。
完整 `.deb` 会安装 Docker、Compose、ADB 并携带 UMI 镜像；源码安装脚本不负责这些系统组件。
GDK 系统库、机器人驱动和硬件固件仍按具体机器人部署。
