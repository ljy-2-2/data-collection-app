# 遥操作中间关节绕行核查

日期：2026-10-20。配置：`physical_left_a_right_b_gripper_half_turn_v9_20261020`。
用户确认的现象：末端位置和朝向正确，但肘部或中间关节的绕法不合理。
本次不连接真机、不修改控制代码或运行参数。数值结果见同目录 `tianji-teleop-posture-audit.json`。

## 结论与证据边界

未发现七轴指令/反馈的正负、编号、度/弧度或右臂 B 通道错误。厂家 FK、URDF、显示和雅可比相互核对通过。末端跟踪正确并不唯一决定七轴姿态；当前问题更符合冗余构型选择及近奇异区行为，而非继续取反某个关节。

已经复现软件中的同类现象，但没有当次真机起始关节角与轨迹，不能断言用户当次运动由某一项单独导致。所有仿真使用理想关节反馈，仅运行 Controller._target；未验证碰撞、真机跟随或从当前位置到样例起点的路径。样例关节值不是可直接执行的复位指令。

## 发现

1. **没有完整的接管姿态保持目标。** `control.py:302` 保存完整 `joint_anchor`，传给求解器后，`ElbowBranchDomain` 只使用其中 J4 判断肘部所在分支及间距；没有 J1/J3/J5 姿态锚定、肘部空间位置或臂角目标。手柄输入是末端位姿，不含操作者肘部追踪。最小化局部关节增量也不保证整段往返后七轴回到原始构型。
2. **零位接管锁定了特定弯肘侧。** J4 分界为 -6.869643733°，配置分支余量为 8°。从 J4=0° 接管时，硬分支条件成为 J4≥0°，不能在持续接管中进入常见的 J4 负向弯肘构型。近奇异区的辅助目标为 J4=+51.130356267°；负分支辅助目标则是 -64.869643733°。这是求解器偏好，不是控制器关节正负错误；辅助并不保证实际到达该角度。
3. **肘部分支边界与物理限位余量混用。** `differential.py:141` 使用 `domain.joint_halfspaces()` 同时计算软限位余量、姿态权重和逃离方向。零位真实关节/腕部不等式最小余量为 59.8°，加入分支面后最小余量变成 0°，因此也会触发“关节边界”辅助。分支面仍应保留为安全约束，但不应未经区分地解释成物理关节到限位的余量；应分开统计和设计辅助策略。
4. **位置优先不是严格位姿保持。** 正常旋转权重为 0.35，近奇异或近边界时最低为 0.05；关节余量恢复项使用位置雅可比的零空间，而非完整位姿零空间，所以可能改变中间关节及末端朝向。即使肉眼看起来夹爪朝向正确，也不能据此认为姿态误差始终为零。
5. **近奇异姿态是主要放大因素，不能只关闭辅助。** 离线关闭肘部辅助与限位逃离项后，零位上移样例最大单轴变化仍为 28.05°，并未消除绕行。该对照只存在于独立仿真配置，没有应用到 App。

## 建议修正顺序

1. 保持已核对的基座、TCP、通道和关节符号，不再通过反号掩盖姿态选择问题。
2. 将真实关节/耦合腕部余量与肘部分支约束分离；保留原有硬约束、速度/加速度和碰撞保护。
3. 明确接管时的期望肘部构型，增加有界的冗余姿态偏好，而不是只把 J4 拉向固定偏置；优先使用完整末端位姿的零空间，避免姿态调整破坏用户目标。
4. 对近奇异起点给出明确提示或限制；先离线验证经过碰撞检查的弯肘准备姿态，不自动换支或发送本报告样例角度。
5. 用关节累计行程、回程构型偏差、末端位置/朝向误差及碰撞余量共同验收，不能只看动画末端箭头正确。

目前仅完成核查与对照，不声称已修复遥操冗余姿态策略。
