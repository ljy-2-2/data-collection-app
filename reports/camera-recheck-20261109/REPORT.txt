2026-11-09 相机“检查设备”恢复修复

已部署：
1. 控制器服务 2.4.3 提供独立 camera_recheck，手动检查不再以历史 recoverable_camera_fault=False 或旧 dmesg 哈希变化永久拒绝重连。
2. 手动检查验证程序哈希、当前 USB 占用/枚举稳定性、控制器实时任务状态，清理经过身份和哈希验证的孤立相机子进程；保留旧故障审计记录。
3. 服务故障上下文保留到同次启动的运行目录，服务重启不会抹去故障证据。Upstart 改为带 2 秒退避的持续重启。
4. 开发板安装包和实际运行工作区的恢复模块/相机客户端/相机检查调度均已更新。只修改开发板及控制器；本机 App 代码未修改。

验证结果：
- 最终版本 19 项离线测试通过，包括旧日志锁定、当前控制器变化、USB 占用、采集中拒绝重连、缺失相机、故障上下文保存/恢复和 App 手动检查路径。
- 实机旧日志锁定可解除，App 能进入重新取流，没有把枚举在线冒充图像正常。
- 相机服务无取流时模拟异常退出，2.03 秒重新启动，PID 20575 -> 20697。
- ZED 单独取流：1280x720，8 秒收到 241 帧，成功解码 JPEG，正常结束。
- 三路取流未通过：初始右腕首帧超时；右腕重置后发生 xHCI 设备枚举失败；其后主相机+左腕组合在左腕首帧超时，尚未进入主相机出帧阶段。App 三路共用取流进程会因此整组停止。

明确撤回的方案：
普通 USBDEVFS_RESET、接口重新授权未恢复右腕。单端口逻辑断开一度重新枚举到新地址，但继续普通 reset 后出现 Setup ERROR / Virt dev invalid / 无法枚举。最终部署代码已移除不可靠的单设备 USBDEVFS_RESET。后续获批并实测通过的专用相机 USB 控制器重新初始化，已另行加入严格条件下的手动检查兜底。

最终恢复与验证：
用户明确批准“仅重新初始化相机 USB 控制器”后，已对 PCI 0000:00:14.0 的原 xhci_hcd 驱动完成解除绑定/重新绑定，并将相机 IRQ 亲和性恢复为 CPU 3。未重启天机、未发送运动或使能命令。前后机器人 PID、模块列表、关键配置哈希相同，实时任务检查通过，最终双臂反馈仍为下使能，根分区恢复并保持只读。
重新初始化后三路重新上线；首次取流时左腕经历一次 USB 断开/重新枚举，下一轮正常：主相机 241 帧/1280x720，右腕 273 帧/1024x768，左腕 247 帧/1024x768。正式观测时长 8 秒，腕部先启动，帧数不能简单除以 8 当作各路帧率。
App 相机专用重连接口连续三次通过，每次持续观察 20 秒，三路 JPEG 均成功解码、帧时间持续递增，无相机错误；详细记录见 app-final-three-reconnects.json 和三张截图。
最终服务进程 21114 正常运行，程序清单哈希核对通过。故障恢复流程可重新尝试当前取流，已消除本轮旧日志永久锁定。

最终按钮行为：
- 重新核查当前状态，不因上一轮 dmesg 哈希变化永久拒绝重连。
- 等待当前真实新帧，不把 RPC 成功或枚举在线当作画面正常。
- 本次点击遇到首帧/启动故障后，最多补做一次检查与取流重试。
- 持续首帧超时、2 秒无新帧、启动/协商失败才会触发专用 USB 控制器兜底；正常检查、单纯传输错误不重置硬件。
- USB 兜底必须验证双臂下使能、没有相机取流进程、接口空闲且无 USB 占用、USB 上只有已知三路相机和 ZED HID、没有 USB 存储，并确认原 xhci_hcd 驱动和 PCI 位置；否则拒绝重置。
- 实机使用本轮真实首帧故障记录在独立 Service 对象回放，确实执行同一恢复函数并返回 usb_controller_reinitialized=true，三路均重新上线；原在线服务未被注入假故障。证据在 fallback-replay-result.json 和 fallback-replay/。
- 正常 App 连续三次检查的审计记录均未触发 USB 重置。

额外实机故障验证：
在三路预览正在出图且无控制、无采集时，单独终止相机服务 PID 20951。2.03 秒后 Upstart 自动拉起 PID 21114；随后调用 App 相机检查入口，三路恢复，继续 20 秒均有持续新帧、无错误。记录见 live-service-interruption.json 和 app-after-service-interruption.json。

限制：
本轮解决的是软件锁定、服务中断和满足条件时的 USB 故障恢复，不等于消除旧 xHCI 驱动所有底层缺陷。重复重连短测不等于长时间运行证明；有其他 USB 设备或机器人仍使能时，系统不会强行重置 USB 控制器。
